### Observability

`plugins/OpenTelemetry.kt` installs `KtorServerTelemetry` and obtains the SDK via `getOpenTelemetry("lettuce")` from the `core` module. `plugins/Monitoring.kt` separately installs Dropwizard metrics (logged via SLF4J every 10s) and the `CallId` plugin using `X-Request-Id`. The SDK is also wired for **logs**: a Logback `OpenTelemetryAppender` (`server/src/main/resources/logback.xml`, the sole root appender) bridges every SLF4J log into the OTel logs SDK, and `getOpenTelemetry` (`core/.../OpenTelemetry.kt`) installs the appender (in `plugins/OpenTelemetry.kt`) and sets the interim exporter to `console`. Defaults are set via `addPropertiesSupplier` (the lowest-precedence config tier) **on purpose**, so the sink can be redirected to a collector by env alone with no code change — set `OTEL_LOGS_EXPORTER=otlp` + `OTEL_EXPORTER_OTLP_ENDPOINT` (the `opentelemetry-exporter-otlp` dep is already on the classpath); `OTEL_TRACES_EXPORTER` likewise. Metrics and traces exporters default to `none` (`otel.metrics.exporter`/`otel.traces.exporter`). **Convention for non-fatal "this should never happen" events:** emit a WARN with the `SHOULD_NEVER_HAPPEN` marker (`MarkerFactory.getMarker`) plus key/value attributes — they flow through the appender to OTel. Reserve it for branches that are genuinely unreachable by ordinary requests (no current usage — `canReadFeedback`'s default-deny used to carry one, but that branch is routinely reached by unauthorized attempts and manager reads, so it was removed).

**Per-request DB metrics (measurement only).** `plugins/RequestTiming.kt` counts each request's statements, transactions and DB time (a `RequestDbMetrics` context element in `core`, filled by an Exposed interceptor) and answers an **authenticated** response with `Server-Timing: db;dur=<ms>;desc="stmt=<n> tx=<m>", app;dur=<ms>` — `perf.serverTiming` (`PERF_SERVER_TIMING`; blank follows the mode: on in development, OFF in production; a production boot with `true` logs a WARN) — **never on an anonymous response** (login, refresh, password reset, the 401 challenge, health, the SPA: statement counts there would be an account-enumeration oracle). Always on, server-side: one `request.slow` INFO line on `ch.nokillswit.perf` for a request at or over `perf.slowRequestMs` (`PERF_SLOW_REQUEST_MS`, default 1000, boot-validated 1..600000; route path without the query string, never bind values). Semantics and the harness: `.claude/docs/performance.md`; pinned by `RequestTimingTest`.

**DB spans (M4, measurement only).** `infra/db/Database.kt` wraps the R2DBC pool with `R2dbcTelemetry` (`opentelemetry-r2dbc-1.0`) **only when a traces exporter other than `none` is configured** (`tracesExporterConfigured()` in `plugins/OpenTelemetry.kt` — system property, then `OTEL_TRACES_EXPORTER`, then core's default `none`; published as `DbSpansEnabledKey`): the default path is the unwrapped pool, because the wrapper costs ~0.1 ms per statement (−36 % throughput at 50 VUs) even when nothing is exported (FINDINGS F18). When on, every statement is a CLIENT span under the request's SERVER span (the SDK is the one `OpenTelemetryKey` publishes; the scaffold PRODUCER/CLIENT `spanKindExtractor` is gone; the pool's validation `SELECT 1` sits below the wrapper and is not traced). Used only by the perf overlay's Jaeger (`perf/run.sh traces`, `.claude/docs/performance.md` "Traces"); pinned by `TracingTest`. **Never export traces from a real deployment without reading this: SERVER spans carry `url.query` (query strings, incl. emails in filters) and the user agent.**
