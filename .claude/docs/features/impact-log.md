### Impact log

The **impact log** (v2.36.0 — the Self-reflection successor) is a per-employee **journal of accomplishments**: each entry carries a required **`title`** (v2.37.0/`V66` — a short single-line identity, **plaintext** `VARCHAR(200)`: lists sort and substring-filter on it, the goals.title rationale; `''` only on pre-V66 rows — validation demands a non-blank title ≤200 on every create/update), covers a **period** (`period_start`/`period_end`, ISO `YYYY-MM-DD` in plaintext `VARCHAR(10)` — lists sort on them; strict zero-padded parse via `parseIsoDateStrict`, start ≤ end, past periods fine, overlaps across entries deliberately allowed — no uniqueness) and tells the story in **four markdown sections**, all required non-blank ≤5000 (`MAX_IMPACT_TEXT_LENGTH`, `validateImpactEntry` in `impactlog/ImpactLog.kt`) and **all four encrypted at rest**: `what_happened`, `contribution`, `why_it_mattered`, `evidence`. Table `impact_log_entries` (`V65`, standard soft-delete), audit table `impact_log_events` (same file — the `goal_events` shape, no comment column: params are content-free, so `ImpactLogEventService` stays cipher-free). Implementation in `server/src/main/kotlin/impactlog/` (`ImpactLogService` — `EncryptedAtRest`, registered in THE Bootstrap list — `ImpactLogEventService`, pure `ImpactLogEvents.kt`/`ImpactLogNotifications.kt` builders, `ImpactLogRoutes.kt`), cloned from goals. **No status machine** — an entry is always live; delete (soft, owner-only, any time) is the only lifecycle.

- **Authorization** (see the resource bullet in `.claude/docs/authorization.md`): the **owner is always the caller** at create (`POST /api/v1/impact-log` carries no user id — no on-behalf create for anyone, ADMIN included); **writes are owner-only** (`requireImpactEntryWrite` — the authorship carve-out of the chain rule: the chain reads, only the owner writes; ADMIN and HR get nothing); **reads** are owner + any manager in the owner's **transitive chain** + the **HR auditor** (audited `hr.read`, resource `impactLog`) at all times (`requireImpactEntryRead` — the `requireDaysOffCorrectionsRead` shape); teammates and non-chain ADMINs get 403. Read-before-guard idiom (missing → 404, forbidden → 403); the write guard runs before `receive` (guard-before-receive, MT-006). Feature-gated by **`IMPACT_LOG`** (standard default-enabled flag) via `impactLogCaller()` — first guard in every handler.
- **List** (`GET /api/v1/impact-log?view=own|managed|user`): `own` (default) = the caller's journal; `managed` = direct reports' journals, widened to the whole transitive chain with `includeIndirect=true` (managed-only, else 400; empty page for non-managers); `user` (HR-only via `requireAuditListAccess`, audited `hr.list`; requires `userId`) = the target's whole journal. **`userId` also doubles as an exact-owner pin-filter on `view=managed`** (v2.38.0 — the days-off shape, backing the person-card drill-down: ANDed onto the reports scope, so an out-of-chain id is just an empty page; still 400 with `view=own`). Sortable `id`/`userName`/`title`/`periodStart`/`periodEnd`/`createdAt`/`lastModified`, default `-periodStart` (most recent periods first); `userName` + `title` substring filters (`containsNormalized`). Rows carry the owner, the **title** (v2.37.0 — it replaced the decrypted what-happened preview), and the period — section texts never list.
- **Events**: `CREATED{periodStart,periodEnd}`, ONE `UPDATED` per edit (`changed` = comma-joined field-name list in stable title→period→sections order, plus `periodStartFrom/To`/`periodEndFrom/To` only when the period moved; a no-op PUT mints nothing), `DELETED{}` — params NEVER carry section text. `GET /api/v1/impact-log/{id}/events`, authorized like the single GET; a soft-deleted entry's trail becomes unreachable through the API (the read preamble 404s), though the DELETED event is minted.
- **Notifications** (see the table in `.claude/docs/features/notifications.md`): every create/update/delete notifies the owner's **DIRECT managers only** (`directManagerIds` — the fan-out-stays-direct rule; the chain above reads on demand; the acting owner is never notified; a manager-less owner notifies nobody; a no-op PUT notifies nobody). Types `IMPACT_ENTRY_CREATED/UPDATED/DELETED_TO_MANAGER`, params `{author, periodStart, periodEnd}` (content-free), link `/impact-log/{id}/view` (deleted → `/impact-log?tab=managed`). Descriptors are built inside the service's mutation transaction and persisted by the route (the consistency model).
