### Migration catalog (V1–V46)

The per-migration history of the schema. Read this before adding a migration or reasoning about schema history; the persistence rules live in `.claude/docs/persistence.md`.

Current migrations are `V1`–`V46`: schema for users/teams/feedbacks/revoked-tokens; the `users.role` column (`V5`); the `admin@lettuce.local` seed (`V6`); soft-delete `marked_as_deleted` columns (with index) on `users` (`V7`), `teams` (`V8`), `templates` (`V16`), `notifications` (`V17`), and `feedbacks` (`V19`); a demo-org seed (`V9`); a feedback templates table (`V10`); the `REJECTED` feedback status (`V11`); a feedback `last_modified` column (`V12`); the `notifications` table (`V13`); a seed of four default feedback templates (`V14`, idempotent via `ON CONFLICT (name)`); the `feedback_events` audit table (`V15`, `ON DELETE CASCADE` from `feedbacks`); partial unique indexes that free `templates.name` (`V16`) and `users.email` (`V18`) on soft-delete (see "Soft delete" in `.claude/docs/persistence.md`); the nullable `feedbacks.requester_message` column (`V20`, see "Requester message" in `.claude/docs/features/feedbacks.md`); `users.password_changed_at` (`V21`, epoch millis, `0` = never — used to invalidate refresh tokens on password change, see "Session auto-extension" in `.claude/docs/authorization.md`); the `alerts` table (`V22`, soft-delete column included — see "Alerts" in `.claude/docs/features/alerts.md`); the 1:1 meeting tables (`V23` — `one_on_one_meetings` with soft-delete, plus the hard-deleting detail tables `one_on_one_notes` and `one_on_one_action_items`, the latter with a self-FK `copied_from_id ON DELETE SET NULL` carry-over chain); the `one_on_one_events` audit table (`V24`, a clone of `V15` — see "1:1 meetings" in `.claude/docs/features/one-on-ones.md`); the `goals` table (`V25`, soft-delete column and the NOT NULL ISO `due_date` included — see "Goals" in `.claude/docs/features/goals.md`); the `goal_events` audit table (`V26`, another `V15` clone); the `user_roles` join table (`V27` — additional roles per user, backfills `ADMIN` rows from and then drops the V5 `users.role` column; no CHECK on `role`, the application enum is the whitelist); the `team_kpis` table (`V28` — soft-delete included, `team_id` FK, deliberately **no manager_id** column, NOT NULL value columns, the nullable denormalized `current_value_date`, and the `ARCHIVED` status CHECK — see "Team KPIs" in `.claude/docs/features/team-kpis.md`); the `team_kpi_events` audit table (`V29`, another `V15` clone); the hard-deleting `team_kpi_values` detail table (`V30` — one (date, value) data point per row, `UNIQUE (team_kpi_id, value_date)`, see "Team KPIs" in `.claude/docs/features/team-kpis.md`); and the `dictionary_entries` table (`V31` — the three global dictionaries in one table discriminated by the enum-name `dictionary` column (no CHECK, the V27 idiom), `position` for the admin-curated order, soft-delete included, and the partial unique index `uq_dictionary_entries_value_active` on `(dictionary, value)` — see "Dictionaries" in `.claude/docs/features/dictionaries.md`); the dictionary defaults seed (`V32` — additive/idempotent via `ON CONFLICT` on that partial index); the users' career-profile refs (`V33` — three nullable `career_path_id`/`career_specialization_id`/`seniority_level_id` FKs into `dictionary_entries`, no ON DELETE since entries never hard-delete — see "Dictionaries" in `.claude/docs/features/dictionaries.md`); the `review_periods` registry (`V34` — `YYYY-MM` VARCHAR(7) month bounds, `UNIQUE (start_month)` as the concurrency backstop, deliberately **no soft-delete** — see "Performance reviews" in `.claude/docs/features/performance-reviews.md`); the `performance_reviews` table (`V35` — soft-delete included, four nullable `*_rating` + four encrypted `*_summary` columns (ratings originally `SMALLINT CHECK 1–6`, encrypted TEXT since `V45`), the `period_id` FK, and the partial unique index `uq_performance_reviews_subordinate_period_active` on `(subordinate_id, period_id)` enforcing one active review per subordinate and period); and the `performance_review_events` audit table (`V36`, another `V15` clone). The goals CLOSED→ARCHIVED terminal-status rename (`V37`, v1.41.0 — rewrites `goals.status`, the STATUS_CHANGED `goal_events` params, and stored `GOAL_CLOSED_TO_SUBORDINATE` notification rows, and recreates the status CHECK). The days-off feature (v1.42.0): `users.paid_days_off_allowance` (`V38` — nullable whole-days INT, ADMIN-only assignable, the V33 precedent), the `public_holidays` registry (`V39` — `UNIQUE (holiday_date)`, hard-deleting), and the `days_off_requests` table (`V40` — soft-delete included, ISO `VARCHAR(10)` period bounds, edge-half booleans, the frozen `cost_half_days`, and the resolution/cancellation stamps — see "Days off" in `.claude/docs/features/days-off.md`). The Polish statutory-holiday seed (`V41`, v1.43.0 — 2026+2027, additive/idempotent via `ON CONFLICT (holiday_date) DO NOTHING`) and the `days_off_corrections` table (`V42` — soft-delete included, signed `amount_half_days` per budget `year`, encrypted `comment`, display-only `author_id` — see "Days off" in `.claude/docs/features/days-off.md`). The `unaccent` extension (`V43`, v1.47.0 — `CREATE EXTENSION IF NOT EXISTS unaccent`, no schema objects of our own; TRUSTED since PG 13 so the owning role needs no superuser. Backs the diacritics-insensitive substring filters: every list text filter renders `LOWER(public.unaccent(col)) LIKE LOWER(public.unaccent(?))` via `containsNormalized` in `infra/db/Sql.kt` — see "List endpoint conventions" in `.claude/docs/list-endpoints.md`). The reversible `users.deactivated` flag (`V44`, v1.48.0 — `BOOLEAN NOT NULL DEFAULT FALSE`, no index; orthogonal to the V7 soft-delete: blocks login/refresh/reset and NEW assignments while historical data stays readable and the V18 partial email index deliberately keeps the email reserved — see "Authorization model" in `.claude/docs/authorization.md`). Encrypted review ratings (`V45`, v1.49.0 — drops the four auto-named 1–6 CHECKs, converts the four `performance_reviews.*_rating` columns `SMALLINT → TEXT USING ::text` so they hold `enc:v1:` envelopes like their summary siblings (legacy plaintext digits wrapped by the boot backfill), and scrubs the `from`/`to` rating values out of stored `RATING_CHANGED` `performance_review_events.params` — see "Encryption at rest" in `.claude/docs/security.md`). The `user_disabled_features` join table (`V46`, v1.53.0 — per-user feature flags: the DISABLED set, composite PK `(user_id, feature)`, `ON DELETE CASCADE`, `VARCHAR(30)` with no CHECK (the V27 idiom — the `Feature` enum is the whitelist), an index on `feature` backing the admin per-feature list filter, and no backfill — no row = enabled, so every user defaults to full access; see "Authorization model" in `.claude/docs/authorization.md`). The `feedback_events` table (`V15`) stores events **structurally** (`event_type` + a JSON `params` map) so the SPA localizes them — see "Feedback events" in `.claude/docs/features/feedbacks.md`.
