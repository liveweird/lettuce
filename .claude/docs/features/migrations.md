### Migration catalog (V1–V63)

The per-migration history of the schema. Read this before adding a migration or reasoning about schema history; the persistence rules live in `.claude/docs/persistence.md`.

Current migrations are `V1`–`V63`: schema for users/teams/feedbacks/revoked-tokens; the `users.role` column (`V5`); the `admin@lettuce.local` seed (`V6`); soft-delete `marked_as_deleted` columns (with index) on `users` (`V7`), `teams` (`V8`), `templates` (`V16`), `notifications` (`V17`), and `feedbacks` (`V19`); a demo-org seed (`V9`); a feedback templates table (`V10`); the `REJECTED` feedback status (`V11`); a feedback `last_modified` column (`V12`); the `notifications` table (`V13`); a seed of four default feedback templates (`V14`, idempotent via `ON CONFLICT (name)`); the `feedback_events` audit table (`V15`, `ON DELETE CASCADE` from `feedbacks`); partial unique indexes that free `templates.name` (`V16`) and `users.email` (`V18`) on soft-delete (see "Soft delete" in `.claude/docs/persistence.md`); the nullable `feedbacks.requester_message` column (`V20`, see "Requester message" in `.claude/docs/features/feedbacks.md`); `users.password_changed_at` (`V21`, epoch millis, `0` = never — used to invalidate refresh tokens on password change, see "Session auto-extension" in `.claude/docs/authorization.md`); the `alerts` table (`V22`, soft-delete column included — see "Alerts" in `.claude/docs/features/alerts.md`); the 1:1 meeting tables (`V23` — `one_on_one_meetings` with soft-delete, plus the hard-deleting detail tables `one_on_one_notes` and `one_on_one_action_items`, the latter with a self-FK `copied_from_id ON DELETE SET NULL` carry-over chain); the `one_on_one_events` audit table (`V24`, a clone of `V15` — see "1:1 meetings" in `.claude/docs/features/one-on-ones.md`); the `goals` table (`V25`, soft-delete column and the NOT NULL ISO `due_date` included — see "Goals" in `.claude/docs/features/goals.md`); the `goal_events` audit table (`V26`, another `V15` clone); the `user_roles` join table (`V27` — additional roles per user, backfills `ADMIN` rows from and then drops the V5 `users.role` column; no CHECK on `role`, the application enum is the whitelist); the `team_kpis` table (`V28` — soft-delete included, `team_id` FK, deliberately **no manager_id** column, NOT NULL value columns, the nullable denormalized `current_value_date`, and the `ARCHIVED` status CHECK — see "Team KPIs" in `.claude/docs/features/team-kpis.md`); the `team_kpi_events` audit table (`V29`, another `V15` clone); the hard-deleting `team_kpi_values` detail table (`V30` — one (date, value) data point per row, `UNIQUE (team_kpi_id, value_date)`, see "Team KPIs" in `.claude/docs/features/team-kpis.md`); and the `dictionary_entries` table (`V31` — the three global dictionaries in one table discriminated by the enum-name `dictionary` column (no CHECK, the V27 idiom), `position` for the admin-curated order, soft-delete included, and the partial unique index `uq_dictionary_entries_value_active` on `(dictionary, value)` — see "Dictionaries" in `.claude/docs/features/dictionaries.md`); the dictionary defaults seed (`V32` — additive/idempotent via `ON CONFLICT` on that partial index); the users' career-profile refs (`V33` — three nullable `career_path_id`/`career_specialization_id`/`seniority_level_id` FKs into `dictionary_entries`, no ON DELETE since entries never hard-delete — see "Dictionaries" in `.claude/docs/features/dictionaries.md`); the `review_periods` registry (`V34` — `YYYY-MM` VARCHAR(7) month bounds, `UNIQUE (start_month)` as the concurrency backstop, deliberately **no soft-delete** — see "Performance reviews" in `.claude/docs/features/performance-reviews.md`); the `performance_reviews` table (`V35` — soft-delete included, four nullable `*_rating` + four encrypted `*_summary` columns (ratings originally `SMALLINT CHECK 1–6`, encrypted TEXT since `V45`), the `period_id` FK, and the partial unique index `uq_performance_reviews_subordinate_period_active` on `(subordinate_id, period_id)` enforcing one active review per subordinate and period); and the `performance_review_events` audit table (`V36`, another `V15` clone). The goals CLOSED→ARCHIVED terminal-status rename (`V37`, v1.41.0 — rewrites `goals.status`, the STATUS_CHANGED `goal_events` params, and stored `GOAL_CLOSED_TO_SUBORDINATE` notification rows, and recreates the status CHECK). The days-off feature (v1.42.0): `users.paid_days_off_allowance` (`V38` — nullable whole-days INT, ADMIN-only assignable, the V33 precedent), the `public_holidays` registry (`V39` — `UNIQUE (holiday_date)`, hard-deleting), and the `days_off_requests` table (`V40` — soft-delete included, ISO `VARCHAR(10)` period bounds, edge-half booleans, the frozen `cost_half_days`, and the resolution/cancellation stamps — see "Days off" in `.claude/docs/features/days-off.md`). The Polish statutory-holiday seed (`V41`, v1.43.0 — 2026+2027, additive/idempotent via `ON CONFLICT (holiday_date) DO NOTHING`) and the `days_off_corrections` table (`V42` — soft-delete included, signed `amount_half_days` per budget `year`, encrypted `comment`, display-only `author_id` — see "Days off" in `.claude/docs/features/days-off.md`). The `unaccent` extension (`V43`, v1.47.0 — `CREATE EXTENSION IF NOT EXISTS unaccent`, no schema objects of our own; TRUSTED since PG 13 so the owning role needs no superuser. Backs the diacritics-insensitive substring filters: every list text filter renders `LOWER(public.unaccent(col)) LIKE LOWER(public.unaccent(?))` via `containsNormalized` in `infra/db/Sql.kt` — see "List endpoint conventions" in `.claude/docs/list-endpoints.md`). The reversible `users.deactivated` flag (`V44`, v1.48.0 — `BOOLEAN NOT NULL DEFAULT FALSE`, no index; orthogonal to the V7 soft-delete: blocks login/refresh/reset and NEW assignments while historical data stays readable and the V18 partial email index deliberately keeps the email reserved — see "Authorization model" in `.claude/docs/authorization.md`). Encrypted review ratings (`V45`, v1.49.0 — drops the four auto-named 1–6 CHECKs, converts the four `performance_reviews.*_rating` columns `SMALLINT → TEXT USING ::text` so they hold `enc:v1:` envelopes like their summary siblings (legacy plaintext digits wrapped by the boot backfill), and scrubs the `from`/`to` rating values out of stored `RATING_CHANGED` `performance_review_events.params` — see "Encryption at rest" in `.claude/docs/security.md`). The `user_disabled_features` join table (`V46`, v1.53.0 — per-user feature flags: the DISABLED set, composite PK `(user_id, feature)`, `ON DELETE CASCADE`, `VARCHAR(30)` with no CHECK (the V27 idiom — the `Feature` enum is the whitelist), an index on `feature` backing the admin per-feature list filter, and no backfill — no row = enabled, so every user defaults to full access; see "Authorization model" in `.claude/docs/authorization.md`). The pulse-surveys feature (v2.0.0): the `app_settings` K/V store (`V47` — the first runtime-editable config, hard-upsert rows, no CHECK on key, idempotent seed of `pulse.cadenceWeeks`/`pulse.openDays`); the `pulse_cycles` table (`V48` — status CHECK, advisory ISO planned dates, the rotating-question FK + snapshotted text, soft-delete included, and the one-non-terminal-cycle partial unique index `uq_pulse_cycles_non_terminal` over a constant); the pulse participation/response pair (`V49` — `pulse_participants` composite-PK eligibility snapshot and `pulse_responses` with `UNIQUE (cycle_id, user_id)`, an FK into the participants pair, and the seven encrypted answer/comment columns — no soft-delete, responses are audit-retained); and the rotating-question bank seed (`V50` — the six `PULSE_ROTATING_QUESTION` statements, additive/idempotent via the V31 partial index — see "Pulse surveys" in `.claude/docs/features/pulse-surveys.md`). The `users.email_notifications_enabled` flag (`V51`, v2.3.0 — `BOOLEAN NOT NULL DEFAULT TRUE`, no index; the per-user email-mirror opt-out: while true every minted in-app notification is also emailed to the recipient, read at send time by `notifications/NotificationEmailer.kt` — flipped only via `PUT /users/{id}/email-notifications`, see "Email mirror" in `.claude/docs/features/notifications.md`). The MFA disabled-flag seed (`V52`, v2.4.0 — `INSERT INTO user_disabled_features … SELECT id, 'MFA' FROM users ON CONFLICT DO NOTHING`, soft-deleted and deactivated rows included: the `MFA` feature value is the one INVERTED-default flag, opt-in email MFA at login, so every pre-existing user starts disabled; `UserService.create` inserts the same row for every user created afterwards, and `TestSeedState.restoreSeedAccounts` re-inserts it on the seed accounts — see "Email MFA" in `.claude/docs/security.md`). Bilingual dictionaries (`V53`, v2.6.0 — renames `dictionary_entries.value` to `value_en`, adds NOT NULL `value_pl` (backfilled as a copy of the English, then real Polish translations for the still-unrenamed V32/V50 seed values — seniority levels and language names deliberately keep their English loanwords), replaces `uq_dictionary_entries_value_active` with the per-language pair `uq_dictionary_entries_value_en_active`/`uq_dictionary_entries_value_pl_active`, and applies the same rename+add to the `pulse_cycles` snapshot: `rotating_question_text` → `rotating_question_text_en` plus `rotating_question_text_pl` backfilled from the referenced entry's new Polish value — a documented one-time deviation from strict snapshot semantics for pre-V53 cycles; see "Dictionaries" in `.claude/docs/features/dictionaries.md`). The goal-event comment column (`V54`, v2.8.0 — `goal_events.comment TEXT NULL`: the optional progress-update context, encrypted at rest by `GoalEventService` (the first encrypted column on an `*_events` table — params stay plaintext and content-free); backs the shared progress write where both parties may update an ACTIVE goal — see "Goals" in `.claude/docs/features/goals.md`). The untouched-goal-value reset (`V55`, v2.8.1 — fresh goals no longer auto-initialize their current value to the type's zero, so this NULLs `current_value`/`achieved` for goals with NO `PROGRESS_UPDATED`/`ACHIEVED_CHANGED` event in `goal_events`; the event-based heuristic keeps every deliberately recorded zero, soft-deleted rows included). The PLAN milestone rebuild (`V56`, v2.9.0 — creates the hard-deleting `goal_milestones` detail table (`goal_id` CASCADE FK, `position`, encrypted `description`, plain `done`); renames the goal type `BINARY` → `PLAN` via the V37 drop-CHECK/rewrite/re-add idiom; converts every ex-BINARY goal — soft-deleted included — to a single plaintext 'Done' milestone carrying `COALESCE(achieved, FALSE)` (the boot `encryptLegacyRows` backfill encrypts it); drops `goals.achieved`; and rewrites `"BINARY"` to `"PLAN"` in stored `CREATED`/`TYPE_CHANGED` `goal_events` params so the SPA needs no legacy label — see "Goals" in `.claude/docs/features/goals.md`). The career position history (`V57`, v2.15.0 — creates `user_career_positions`: the V42 corrections shape (BIGSERIAL id, `user_id` FK, `created_at`/`last_modified` epoch ms, soft-delete + its index) with a strict-ISO `start_date VARCHAR(10)` (lexicographic == chronological, the V34 idiom), three nullable `dictionary_entries` refs (no ON DELETE — the V33 precedent), and the partial unique `uq_user_career_positions_user_start_active` on `(user_id, start_date)` over active rows (same-day race backstop + freed pairs on soft-delete); then DROPS the three V33 `users.career_*_id` columns with NO data copy — histories deliberately start empty, the current triple everywhere now derives from the latest position — see "Career progression" in `.claude/docs/features/dictionaries.md`). The stored career-position end date (`V58`, v2.17.0 — `user_career_positions.end_date VARCHAR(10) NULL`, the same strict-ISO idiom as `start_date`: the ONE exception to the V57 start-only model, written exclusively by account deactivation (today stamped on the final active position; reactivation clears it, a DELETE of the stamped row transfers it to the surviving final row) — non-final rows keep their derived ends, see "Career progression" in `.claude/docs/features/dictionaries.md`). The optional user unique id (`V59`, v2.19.0 — `users.unique_id VARCHAR(50) NULL`, an employee-id-like reference, ADMIN-only assignable via POST/PUT with the allowance's null=leave-unchanged/no-clearing semantics; uniqueness is the V18 email convention — the partial unique index `uq_users_unique_id_active` over active rows, so a soft-deleted user frees their id, and NULLs are distinct so any number of users may have none — see "Authorization model" in `.claude/docs/authorization.md`). The multilingual dictionaries (`V60`, v2.20.0 — adds `dictionary_entries.translations TEXT NOT NULL DEFAULT '{}'` (the JSON `{lang->value}` map, the notifications-params idiom), backfills `{'pl': value_pl}` unconditionally (V53's copy-EN rows included — zero API-visible change), and DROPS `value_pl` (its partial unique index goes with it — non-EN uniqueness is validation-level since the whole-document PUT payload IS the post-save active set; `uq_dictionary_entries_value_en_active` stays as the default-language DB backstop); the same add/backfill/drop applies to the `pulse_cycles` snapshot: `rotating_question_translations` replaces `rotating_question_text_pl` — see "Dictionaries" in `.claude/docs/features/dictionaries.md`). The per-user language (`V61`, v2.21.0 — `users.language VARCHAR(10) NOT NULL DEFAULT 'en'`, the V44/V51 idiom: no index, no CHECK — `SUPPORTED_LANGUAGES` in `dictionaries/Languages.kt` is the whitelist; drives the UI at sign-in and every server-composed email's language, set at create and changed only via `PUT /users/{id}/language` — see "Authorization model" in `.claude/docs/authorization.md`). The team-KPI creator (`V62`, v2.26.0 — `team_kpis.created_by BIGINT NOT NULL REFERENCES users ON DELETE RESTRICT`, added nullable → correlated-backfilled from `teams.manager_id` (the V53 UPDATE...FROM shape — existing rows' creator was by definition the team's manager) → `SET NOT NULL`; purely INFORMATIONAL — the Creator column; authorization stays keyed on `teams.manager_id` + the management chain, never on this column — see "Team KPIs" in `.claude/docs/features/team-kpis.md`). The days-off cancellation record (`V63`, v2.31.0 — `days_off_requests.cancelled_by BIGINT NULL REFERENCES users` + `cancel_reason TEXT NULL`: cancellation reworked to owner-or-chain-manager with a mandatory reason, so the actor is stamped and the reason stored encrypted at rest (the V54 nullable-encrypted-column shape); both NULL on pre-rework cancellations — see "Days off" in `.claude/docs/features/days-off.md`). The `feedback_events` table (`V15`) stores events **structurally** (`event_type` + a JSON `params` map) so the SPA localizes them — see "Feedback events" in `.claude/docs/features/feedbacks.md`.
