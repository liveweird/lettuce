### List endpoint conventions

`GET /api/v1/users`, `GET /api/v1/teams`, `GET /api/v1/teams/members`, `GET /api/v1/feedbacks`, `GET /api/v1/one-on-ones`, `GET /api/v1/one-on-ones/action-items` (v4.19.0 — the caller's open action items, see `.claude/docs/features/one-on-ones.md`), `GET /api/v1/goals`, `GET /api/v1/team-kpis`, `GET /api/v1/performance-reviews`, `GET /api/v1/days-off`, `GET /api/v1/impact-log`, `GET /api/v1/succession-plans`, `GET /api/v1/templates`, `GET /api/v1/notifications`, `GET /api/v1/users/{id}/activity` (v4.9.0 — the person-anchored activity log, see the paragraph below), `GET /api/v1/shares` (v4.8.0 — `view=withMe|byMe|document`, default `withMe`; `resourceType` equality + repeated-key `IN` `status` filters; `resourceId` only with, and required by, `view=document`; sort `id|createdAt|expiresOn`, default `-createdAt`; the shape `400`s precede the author/own-right gate; `withMe` hides WITHDRAWN rows and the types of the caller's disabled features in SQL — see `.claude/docs/features/sharing.md`), and `GET /api/v1/alerts` are list endpoints; every list endpoint follows the standard list rules (owned by `api-guidelines/API-GUIDELINES.md`, summarized below). The OpenAPI spec is the contract; document the query params for each list endpoint there. **Row enrichments, view semantics and filter inventory** — `teams/members` (`view=member|managed|managers`, `includeIndirect`, the route-side dashboard stats, the gated `seniorityLevel`/`lastLoginAt` fields, the `deactivated` filter), the users-list `teams`, the teams-list `memberIds`/`asOf`, the kudos `content`, the days-off scope `teams`, the activity-log composite ordering, and the project-state notes on repeated-key `IN` filters and per-column substring filters — live in **`.claude/docs/list-endpoints-details.md`**, a MANDATORY read before adding or changing a list endpoint's params, views or row fields. (Rules that hold everywhere: a repeated key on a scalar param is a `400`; `seniorityLevel` and `lastLoginAt` are attached only on `view=managed`, for an HR caller, or on the caller's own row.)

**The generic list rules are owned by `api-guidelines/API-GUIDELINES.md`** (see "API guidelines" in the root CLAUDE.md) — summary: offset pagination `page`/`pageSize` (1-based, default 20, max 100; out-of-range → `400`) in the `{items, page, pageSize, total}` envelope, `total` after filters before pagination with count + page rows in the same `suspendTransaction` (cursor paging is a documented per-endpoint opt-in) [API-LIST-001/002, API-STRUCT-004]; `sort=field`/`-field`, comma-separated multi-field, per-endpoint whitelist → `400`, `id` asc always appended as tiebreaker, default `id` asc documented [API-LIST-003]; whitelisted equality filters on the field's own name plus `field[gte|gt|lte|lt]` bracket operators only where needed, strict `true`/`false` booleans, enums by string name, repeated key reserved for `IN` [API-LIST-004]; `q` free-text first, per-column substring only when a UI requires it [API-LIST-005]; camelCase params, reusable `Page`/`PageSize`/`Sort` under `#/components/parameters` `$ref`'d from each list path, one `*Page` envelope schema per resource, sortable/filterable whitelists documented per path [API-NAME-001..004].

**Implementation.**

- The shared helper lives at `infra/paging/Paging.kt`: `ApplicationCall.parsePaging(...)` parses `page`/`pageSize`/`sort` from the query string and validates against per-endpoint whitelists into a `PageRequest`; `Query.applyPaging(req, columns)` applies `.limit(...).offset(...)` + `.orderBy(...)` to an Exposed `Query`. Validation failures throw a typed exception that `StatusPages` maps to `400` + `ProblemDetail`. New list endpoints reuse these rather than re-parsing params.
- **Every per-column substring filter is case- AND accent-insensitive** (v1.47.0): use `column.containsNormalized(value)` from `infra/db/Sql.kt` — it renders `LOWER(public.unaccent(col)) LIKE LOWER(public.unaccent(?))` (extension enabled in `V43`), so "zolw" matches "Żółw" and vice versa. Never hand-roll `lowerCase() like containsPattern(...)` (the pattern builder is `internal` for exactly that reason), and keep unaccent-before-LOWER — the reverse breaks uppercase-diacritic input under the C-locale database. The SPA mirrors the rule client-side: Mantine searchable Select/MultiSelect filtering goes through the theme-level `foldedOptionsFilter` (`web/src/utils/text.ts`, see `web/CLAUDE.md`).
- **Query budgets:** a list endpoint should cost the same number of statements and transactions for 1 row as for 50 (no per-row query). `QueryBudgetTest` pins this from `Server-Timing` for the endpoints in its `BUDGETS` table; every budgeted endpoint is O(1) since v4.14.0 (an endpoint that is ALREADY O(n) when it is budgeted pins its slope with `dStmt`/`dTx` — the mechanism stays for the next arrival). Add a row when you add or change a list endpoint (see "Query budgets" in `.claude/docs/performance.md`).
