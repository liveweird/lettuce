**The generic list rules are owned by `api-guidelines/API-GUIDELINES.md`** (see "API guidelines" in the root CLAUDE.md) — summary: offset pagination `page`/`pageSize` (1-based, default 20, max 100; out-of-range → `400`) in the `{items, page, pageSize, total}` envelope, `total` after filters before pagination with count + page rows in the same `suspendTransaction` (cursor paging is a documented per-endpoint opt-in) [API-LIST-001/002, API-STRUCT-004]; `sort=field`/`-field`, comma-separated multi-field, per-endpoint whitelist → `400`, `id` asc always appended as tiebreaker, default `id` asc documented [API-LIST-003]; whitelisted equality filters on the field's own name plus `field[gte|gt|lte|lt]` bracket operators only where needed, strict `true`/`false` booleans, enums by string name, repeated key reserved for `IN` [API-LIST-004]; `q` free-text first, per-column substring only when a UI requires it [API-LIST-005]; camelCase params, reusable `Page`/`PageSize`/`Sort` under `#/components/parameters` `$ref`'d from each list path, one `*Page` envelope schema per resource, sortable/filterable whitelists documented per path [API-NAME-001..004].

**Users-list enrichment (v2.1.0):** `GET /api/v1/users` rows additionally carry `teams` — the non-deleted teams the user is a **member** of (`TeamRef` id+name pairs, name-ascending; empty array = none), one grouped join query per page inside the list's transaction. The single-user/create/update responses OMIT the key (`@EncodeDefault(NEVER)` — null would trip the shared response schemas). Backs the `/feature-flags` Teams column; the repeated-key `teamId` filter composes with it. Membership only — managing a team without being on its roster does not list it.

**Kudos-view content enrichment (v2.2.0):** `GET /api/v1/feedbacks?view=kudos` rows additionally carry `content` — the full decrypted text next to the 200-char `contentPreview`; every other view OMITS the key (`@EncodeDefault(NEVER)` — the users-list `teams` idiom above). See "Feedback list views" in `.claude/docs/features/feedbacks.md`.

**Days-off scope-team enrichment (v3.13.0):** `GET /api/v1/days-off?view=managed` and `GET /api/v1/days-off/budgets?view=managed` rows carry `teams` — the teams via which the owner is in the caller's managed scope (the caller's own teams; plus teams managed further down under `includeIndirect`), name-ascending; every other view OMITS the key (`@EncodeDefault(NEVER)`, the users-list `teams` idiom). The calendar's user rows carry the same field unconditionally (see "Days off" in `.claude/docs/features/days-off.md`).

**Activity-log list (v4.9.0):** `GET /api/v1/users/{id}/activity` is a person-anchored sub-resource (API-RES-006) over a `UNION ALL` of the seven per-document event trails, the share rows and the person-keyed days-off and career-position trails, so a row has **no scalar id**: the row `id` is the synthetic string `<AREA>:<SOURCE>:<id>`, the only sortable field is `createdAt` (default `-createdAt`), and the deterministic tiebreaker is the id's own components — `area` ascending, `source` ascending, event id descending — a total order (a registered deviation from API-LIST-003, see the known-gaps register; `parsePaging`'s auto-appended `id` entry is replaced by that composite tiebreak in `SetOperation.applyPaging`, `infra/paging/Paging.kt`). Filters: `area` (enum equality) and the inclusive epoch-millisecond `createdAt[gte]`/`createdAt[lte]` pair (`gte > lte` → 400); count and rows come from one transaction, and the viewer's feature-disabled areas are left out of the union so `total` stays honest (a pinned disabled area → an empty page, never 400). All shape 400s run before the 404 and the role gate. See `.claude/docs/features/activity-log.md`.

**Project-state notes** (implementation status, not rules — update when they change): repeated-key `IN` (v4.13.0, `optionalEnumSet`/`optionalUIntSet` in `infra/paging/QueryParams.kt`: blanks dropped, deduped, ≤100 distinct values else 400, array schema in the spec) is implemented by `status` on feedbacks/goals/team-kpis/performance-reviews/shares, `teamId` on users/teams-members/team-kpis/the days-off calendar (`scope=org`), and days-off `type`+`poolTypeId` (pools narrow only the PAID branch; see `.claude/docs/features/days-off.md`) — **every other key stays a scalar, so a repeated one is a 400** (v2.35.0, MT-003: `singleValue`, which `optionalString` and `parsePaging` both ride — never silent first-value-wins; unknown parameter *names* stay ignored by deliberate leniency, see API-LIST-004); `q` is implemented by **no endpoint yet** (current UIs use per-column filters; add the reusable `Q` parameter with the first endpoint that needs it); per-column substring filters exist today on users (`name`/`email`/`uniqueId`), teams (`name`; member `name`/`email`), templates (`name`), goals (`title`/`managerName`/`subordinateName`), team-kpis (`title`/`teamName`), feedbacks (the three party names — `subjectName` matches ANY recipient of a multi-recipient row since v3.1.0, and the `subjectId` equality filter likewise tests membership; `sort=subjectName` orders by the first recipient), 1:1s and reviews (`managerName`/`subordinateName`), days-off (`userName`; plus the repeated-key `poolTypeId` filter, v3.2.0 — the paid pool kind, narrowing the PAID branch; with a PAID-less `type` set it is a 400), impact-log (`userName`/`title`), succession-plans (`userName`/`managerName`), and alerts (`title`) — all through the shared `containsNormalized`.

**Implementation.**

- The shared helper lives at `infra/paging/Paging.kt`: `ApplicationCall.parsePaging(...)` parses `page`/`pageSize`/`sort` from the query string and validates against per-endpoint whitelists into a `PageRequest`; `Query.applyPaging(req, columns)` applies `.limit(...).offset(...)` + `.orderBy(...)` to an Exposed `Query`. Validation failures throw a typed exception that `StatusPages` maps to `400` + `ProblemDetail`. New list endpoints reuse these rather than re-parsing params.
- **Every per-column substring filter is case- AND accent-insensitive** (v1.47.0): use `column.containsNormalized(value)` from `infra/db/Sql.kt` — it renders `LOWER(public.unaccent(col)) LIKE LOWER(public.unaccent(?))` (extension enabled in `V43`), so "zolw" matches "Żółw" and vice versa. Never hand-roll `lowerCase() like containsPattern(...)` (the pattern builder is `internal` for exactly that reason), and keep unaccent-before-LOWER — the reverse breaks uppercase-diacritic input under the C-locale database. The SPA mirrors the rule client-side: Mantine searchable Select/MultiSelect filtering goes through the theme-level `foldedOptionsFilter` (`web/src/utils/text.ts`, see `web/CLAUDE.md`).

- **Query budgets:** a list endpoint must cost the same number of statements and transactions for 1 row as for 50 (no per-row query) — `QueryBudgetTest` pins it from `Server-Timing` (one budget row per endpoint, already-O(n) ones pin their slope; see "Query budgets" in `.claude/docs/performance.md`).
