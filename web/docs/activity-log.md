# Activity log — SPA (v4.9.0, `web/`)

Moved out of `web/CLAUDE.md` so it is read on demand; `web/CLAUDE.md` keeps a mandatory-read pointer here.

The server rules live in `.claude/docs/features/activity-log.md`. SPA, own log (`/activity`, nav leaf "My activity" in My work, ungated, tour id `nav-activity`, a whirlwind stop after Shared): `api/activity.ts` (`listActivity(userId, …)`), `components/ActivityFeed.tsx` (the shared body over `userId`/`storeKey` — persisted keys hold area, date pair, sort and page size) under three pages: `pages/ActivityLog.tsx` (the caller's own log, key `activity.own`) and `pages/UserActivity.tsx` at `/users/:userId/activity` (a report's log for a chain manager, key `userActivity.managed`; the HR auditor's, key `userActivity.audit` — the flavor follows `canAudit()` (HR gets the audited full view server-side before the chain, so an HR viewer always sees the auditor title/hint whatever `?mode` says; a non-auditor `mode=audit` falls back to the report flavor) — the `useDashboardDrillDown("activity")` origin/back conventions, the heading names the person from the user pool, one's own id redirects to `/activity`, and a server `403` — a peer opening the URL — renders "You don't have permission to view this activity log."); entry points: the person card's Profile **Activity** button (`ButtonKey` `activity`, ungated in `FEATURE_OF`, rendered on the card grids where `career` is (the managed view, plus HR viewers) and on the UserDetails page only for a direct report — HR there reaches it through the Audit block instead — and linked through `utils/activityLinks.ts` `userActivityLink`, which routes the signed-in person's own card to `/activity`) and the UserDetails Audit block (`mode=audit`; ungated, so the block now always renders for HR), `utils/describeActivity.ts` and `hooks/useCareerLabels.ts`. **The list is a semantic feed (`<ul>`), not the `EventTimeline` shell**: that shell is a per-document history whose `who · when` line names the same person on every row here, while an activity row needs an area pill, a document link or a "For {person}" line, and a relative time. Filters: the area Select lists only the areas the VIEWER has enabled (`hasFeature`; ungated areas — career, sign-ins — always), and a `DateField` pair maps to `createdAt[gte|lte]` as local-day bounds (an inverted pair is flagged and never sent). **Wording** is client-side and subject-free so it reads right on anyone's log ("Signed in", "Shared a goal with Ben"): document rows dispatch to the SAME per-area describers the documents' History tabs use — **exported from `utils/<area>EventText.ts`** (`describeFeedbackEvent`, `describeGoalEvent`, …; `components/*History.tsx` import them — they live in `.ts` siblings because `react-refresh/only-export-components` is an error for a component file), loosened to `Pick<Event, "type" | "params">`; share, days-off, career and sign-in rows are worded in `describeActivity.ts` from `activity.event.*` (context variants: `until`, `byAuthor`, an `ADD`/`SUBTRACT` operation, `from`, `mfa`, `empty`). A pulse-results share row (v4.12.0) has its own share-only `PULSE_TEAM_RESULTS` area (gated by `PULSE_SURVEYS`), names the team from the snapshot (`activity.shareNoun(Of).PULSE_TEAM_RESULTS_named`) and, for a non-sharee viewer, opens `/pulse?tab=results&team={id}` (`shareOpenPath`). Career rows prefer the LIVE localized dictionary label by entry id (`useCareerLabels`, fetched only while a career row is on the page) and fall back to the display name frozen on the event. The document label is `documentLabel` (`utils/shareKinds.ts`, shared with the Shared screen) over the row's `details`; a document row with no `link` (the log's owner can no longer read it) shows a muted "No longer available" while the sentence stays. Tests: `pages/ActivityLog.test.tsx`, `pages/UserActivity.test.tsx`, `utils/describeActivity.test.ts` (every area x eventType in EN and PL), `utils/activityLinks.test.ts`, the person-card cases in `TeamMembersTable`/`ManagersTable`/`UserDetails` tests, the nav/tour pins; e2e `activity-log.spec.ts`.
