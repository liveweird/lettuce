# Language switch

- **Spec**: [tests/i18n.spec.ts](../tests/i18n.spec.ts)
- **Actors**: the seed administrator (to create the throwaway user), then a throwaway user
- **Owns** (exclusive server-side state): one throwaway user (created by the journey) whose
  server-side language it flips — since v2.21.0 the switch persists on the server (the one
  synced per-user language), so the journey never mutates a seeded account

## Scenario: language switch to Polish persists across reload and re-login

1. The admin signs in, creates a throwaway user through the real UI, and signs out.
2. The throwaway user signs in through the real login form (the form path is what applies the
   server-stored language to the UI).
   - *Expected*: the **Dashboard** heading is visible (English chrome — the account was
     created with the English default).
3. The user opens the header language menu and picks **Polski** (entries are the languages'
   native names, readable before switching).
   - *Expected*: the chrome translates to Polish — the **Pulpit** heading and the
     **Moi podwładni** tab are visible. The choice is also saved to the server.
4. The user reloads the page.
   - *Expected*: still Polish — the **Pulpit** heading is visible; the device choice persisted.
5. All device state is wiped (browser storage cleared — the locally cached language included)
   and the user signs in again through the login form.
   - *Expected*: the UI comes up in Polish purely from the SERVER-stored language — the
     **Pulpit** heading is visible. This is the v2.21.0 sync proof.
